# RFC-0024 — Graph Serialization

**Status:** Draft

**Version:** 0.1

Depends on:

- RFC-0001 Capability Graph
- RFC-0007 Execution Graph
- RFC-0017 Resource Model

---

# Цель

Определить единый формат
сохранения,
обмена
и передачи графов ICG.

---

# Главная идея

Graph —

первоклассная сущность.

Он должен свободно

- сохраняться;

- передаваться;

- объединяться;

- подписываться;

- версионироваться.

---

# Архитектура

```
Capability Graph

↓

Serializer

↓

ICG Graph Format

↓

Deserializer

↓

Capability Graph
```

---

# Формат

MVP использует

```
JSON
```

Позже могут поддерживаться

```
YAML

CBOR

MessagePack

Protocol Buffers
```

---

# Graph Model

Минимальная структура

```yaml
version:

nodes:

edges:

metadata:
```

---

# Node

Каждая вершина содержит

```yaml
id

type

attributes
```

---

# Edge

Каждое ребро содержит

```yaml
source

target

weight

metadata
```

---

# Metadata

Graph может содержать

```
author

created_at

description

signature
```

---

# Versioning

Каждый Graph имеет

```
graph_version
```

Serializer обязан
поддерживать миграцию
между версиями.

---

# Partial Graph

Разрешается
сохранять

не весь Graph,

а только подграф.

Например

```
Capability Graph

↓

Reasoning Subgraph
```

---

# Merge

Serializer обязан
поддерживать объединение Graph.

Например

```
Local Graph

+

Downloaded Graph

↓

Merged Graph
```

---

# Signatures

Graph может быть подписан.

Например

```
Graph

↓

Signature

↓

Verification
```

Это позволит безопасно
обмениваться Graph.

---

# Compression

Serializer может использовать

```
gzip

zstd
```

для больших Graph.

---

# Interoperability

Graph Format

не зависит

от языка программирования.

Любая реализация

ICG

должна понимать формат.

---

# Future

Позже Graph Format сможет содержать

```
Embeddings

Execution History

Route Profiles

Resource Snapshots

Capability Metrics
```

Без изменения базовой структуры.

---

# Acceptance Criteria

✓ существует единый формат Graph;

✓ Graph можно сохранить;

✓ Graph можно восстановить;

✓ поддерживается Versioning;

✓ поддерживается Merge;

✓ поддерживаются подписи;

✓ формат независим от языка реализации.
