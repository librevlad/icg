# RFC-0013 — Capability Schema

**Status:** Draft

**Version:** 0.1

Depends on:

- RFC-0001 Capability Graph
- RFC-0002 Contract
- RFC-0012 Provider SDK

---

# Цель

Определить универсальную модель Capability.

Capability является основной единицей абстракции ICG.

Provider реализует Capability.

Planner требует Capability.

Policy выбирает Provider.

Executor исполняет Capability.

---

# Главная идея

Capability —

не строка.

Не функция.

Не команда.

Capability —

контракт между Planner и Provider.

---

# Архитектура

```
Planner

↓

Capability

↓

Graph

↓

Provider

↓

Executor
```

---

# Capability Model

Минимальная структура

```python
Capability

id

version

input_schema

output_schema

constraints

metadata
```

---

# Identity

Каждая Capability имеет
глобальный идентификатор.

Например

```
coding

reasoning

verification

browser.navigation

git.commit
```

---

# Version

Capability обязана иметь версию.

Например

```
coding

1.0
```

Это позволяет развивать
Capability без нарушения совместимости.

---

# Input Schema

Capability определяет,
какие данные она принимает.

Например

```yaml
input:

source_files

instructions

language
```

---

# Output Schema

Capability определяет,
что возвращается.

Например

```yaml
output:

patch

report

artifacts
```

---

# Constraints

Capability может иметь ограничения.

Например

```
offline

network

gpu

filesystem

docker

timeout
```

Planner может учитывать
эти ограничения.

---

# Metadata

Capability может содержать

```
description

tags

examples

documentation
```

Это помогает Discovery
и Planner.

---

# Compatibility

Provider обязан объявить

какие версии Capability
он поддерживает.

Например

```
coding

1.0
```

или

```
coding

2.x
```

---

# Composition

Capability может состоять
из других Capability.

Например

```
testing

↓

build

↓

pytest

↓

coverage
```

Graph может использовать
эту информацию
при построении маршрутов.

---

# Capability Registry

Все Capability
хранятся централизованно.

Например

```
capabilities/

coding.yaml

reasoning.yaml

verification.yaml
```

Graph использует Registry
как источник истины.

---

# Extensibility

Любой Provider
может реализовать
новую Capability.

Но сама Capability
должна быть зарегистрирована.

---

# Что НЕ входит

Capability

не знает

- Provider;

- Executor;

- Planner;

- Memory.

Она описывает
только интерфейс возможности.

---

# Acceptance Criteria

✓ Capability имеет формальную схему;

✓ Capability имеет версию;

✓ Capability описывает Input и Output;

✓ Provider реализует Capability;

✓ Planner использует Capability;

✓ Graph хранит Capability независимо от Provider.
