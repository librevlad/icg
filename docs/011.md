# RFC-0011 — Discovery Service

**Status:** Draft

**Version:** 0.1

Depends on:

- RFC-0001 Capability Graph
- RFC-0006 Execution Policy
- RFC-0008 Memory
- RFC-0010 Event Bus

---

# Цель

Определить механизм,
позволяющий ICG самостоятельно
обнаруживать новые вычислительные возможности.

Discovery является системой
саморасширения Graph.

---

# Основная идея

ICG не должен быть статическим каталогом.

Он должен уметь самостоятельно отвечать на вопрос

> "Что нового появилось в интернете,
что может помочь выполнять задачи лучше?"

---

# Архитектура

```
Internet

↓

Discovery

↓

Candidate

↓

Benchmark

↓

Capability Graph
```

---

# Ответственность

Discovery обязан

- искать новые Provider;
- обнаруживать изменения существующих Provider;
- запускать Benchmark;
- публиковать результаты.

Discovery запрещено

- выполнять пользовательские задачи;
- выбирать Executor;
- изменять Execution Policy.

---

# Источники Discovery

MVP использует ручную регистрацию.

Например

```
provider.yaml
```

Позже Discovery сможет использовать

```
GitHub

HuggingFace

HackerNews

RSS

Awesome Lists

Model Registries

API Directories
```

---

# Candidate

Каждый найденный Provider
сначала становится Candidate.

```
Candidate

↓

Unknown
```

Он еще не входит
в Capability Graph.

---

# Benchmark

Каждый Candidate обязан пройти
стандартизированный Benchmark.

Например

```
Hello World

↓

Generate Function

↓

Refactor

↓

JSON

↓

Patch

↓

Unit Test
```

---

# Capability Detection

Discovery автоматически определяет

```
coding

reasoning

vision

planning

verification

browser

docker
```

если Provider действительно
умеет это делать.

---

# Capability Profile

После Benchmark
формируется профиль.

Например

```yaml
provider:
    gemini-cli

capabilities:

    coding:
        success: 0.95

    reasoning:
        success: 0.99

    json:
        success: 0.98

latency:
    3.2

cost:
    free
```

---

# Registration

После успешного Benchmark

Discovery публикует событие

```
ProviderDiscovered
```

Далее Graph
сам регистрирует Provider.

Discovery не изменяет Graph напрямую.

---

# Event Flow

```
Discovery

↓

ProviderDiscovered

↓

Graph

↓

ProviderRegistered
```

---

# Повторный Benchmark

Каждый Provider
может проверяться повторно.

Например

```
раз в неделю

или

после обновления версии
```

Результаты обновляют
Capability Profile.

---

# Deprecation

Если Provider
перестал работать,

Discovery публикует

```
ProviderUnavailable
```

Graph может

- отключить Provider;
- понизить приоритет;
- сохранить историю.

Provider не удаляется.

---

# Discovery ничего не знает

Discovery запрещено знать

- Engine;

- Planner;

- Executor;

- Workspace;

- User Tasks.

Он занимается исключительно
поиском возможностей.

---

# Capability Evolution

Provider может приобрести
новые Capability.

Например

```
Gemini CLI

↓

Coding

↓

Vision
```

Discovery автоматически
обновляет профиль.

---

# Benchmark Suite

Все Provider проходят
одинаковый набор тестов.

Например

```
Code Generation

Patch Editing

JSON

Reasoning

Refactoring

Documentation
```

Это позволяет
сравнивать их объективно.

---

# Хранение

Discovery
не хранит результаты самостоятельно.

Он публикует события.

Memory сохраняет историю.

Graph обновляет профиль.

---

# Будущее развитие

Позже Discovery сможет поддерживать

```
Automatic Crawling

Plugin Marketplace

Community Registry

Federated Discovery

P2P Discovery

Capability Verification

Continuous Benchmarking

Shadow Testing
```

При этом интерфейс Discovery
не должен измениться.

---

# Пример жизненного цикла

```
Internet

↓

New Provider

↓

Discovery

↓

Benchmark

↓

ProviderDiscovered

↓

Graph

↓

Execution Policy

↓

Production
```

---

# Что НЕ входит

Discovery

не занимается

- выполнением задач;

- выбором маршрута;

- обучением моделей;

- хранением памяти.

Он отвечает исключительно
за обнаружение новых возможностей.

---

# Acceptance Criteria

RFC считается реализованным если

✓ существует компонент Discovery;

✓ новые Provider проходят Benchmark;

✓ Capability определяются автоматически;

✓ Discovery публикует события через Event Bus;

✓ Discovery не изменяет Graph напрямую;

✓ новый Provider можно добавить без изменения Engine;

✓ Capability Profile формируется автоматически;

✓ неработающие Provider корректно помечаются как недоступные.
