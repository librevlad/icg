# RFC-0025 — ICG CLI

**Status:** Draft

**Version:** 0.1

Depends on:

- RFC-0002 Contract
- RFC-0007 Execution Graph
- RFC-0011 Discovery
- RFC-0022 Plugin System

---

# Цель

Определить стандартный интерфейс
взаимодействия пользователя
с ICG.

CLI является
первым официальным интерфейсом системы.

Все остальные интерфейсы
(Web, Desktop, IDE)
строятся поверх CLI.

---

# Главная идея

CLI —

не оболочка вокруг Engine.

CLI —

тонкий клиент ICG Runtime.

Вся бизнес-логика
находится внутри ядра.

---

# Архитектура

```

User

↓

CLI

↓

Engine

↓

Runtime

↓

Providers

```

---

# Принципы

CLI

не содержит

- бизнес-логики;
- маршрутизации;
- планирования;
- Discovery.

Он только
отправляет команды
и отображает результат.

---

# Command Structure

Все команды
имеют одинаковый формат.

```

icg <command> <arguments>

```

---

# Core Commands

### Выполнение контракта

```

icg run contract.yaml

```

---

### Выполнение задачи

```

icg task "Refactor auth module"

```

---

### Проверка состояния

```

icg status

```

---

### Список Provider

```

icg providers

```

---

### Список Capability

```

icg capabilities

```

---

### Просмотр маршрутов

```

icg routes

```

---

### Просмотр Worker

```

icg workers

```

---

### Benchmark

```

icg benchmark

```

или

```

icg benchmark gemini-cli

```

---

### Discovery

```

icg discover

```

---

### Graph

```

icg graph export graph.json

```

```

icg graph import graph.json

```

---

### Plugins

```

icg plugin list

```

```

icg plugin install gemini-cli

```

```

icg plugin remove gemini-cli

```

---

### Memory

```

icg memory stats

```

```

icg memory cleanup

```

---

### Logs

```

icg logs

```

или

```

icg logs --task 381

```

---

### Doctor

Проверка окружения.

```

icg doctor

```

Например

```

✓ Python

✓ Git

✓ Gemini CLI

✓ Docker

✗ Oracle Worker

```

---

### Config

```

icg config show

```

```

icg config edit

```

---

# Output Modes

CLI поддерживает

```

text

json

yaml

table

```

Например

```

icg providers --json

```

---

# Interactive Mode

CLI может запускаться

в интерактивном режиме.

```

icg shell

```

После чего пользователь получает

```

icg>

```

---

# Batch Mode

CLI поддерживает

автоматическое выполнение.

Например

```

icg run *.yaml

```

или

```

icg benchmark all

```

---

# Exit Codes

CLI обязан использовать

стандартные коды возврата.

```

0

Success

1

Error

2

Configuration Error

3

Provider Error

4

Runtime Error

```

---

# Machine Readability

Все команды

могут возвращать

JSON.

Это позволяет

использовать CLI

в CI/CD,

IDE,

GitHub Actions,

других системах.

---

# Future

Позже CLI сможет поддерживать

```

Streaming Logs

Live Dashboard

Remote Runtime

Interactive Graph

TUI

Voice Commands

```

Без изменения архитектуры.

---

# Design Principles

CLI должен быть

```

Predictable

Scriptable

Composable

Human Friendly

Machine Friendly

```

---

# Acceptance Criteria

✓ существует единый CLI;

✓ все функции ядра доступны через CLI;

✓ CLI не содержит бизнес-логики;

✓ поддерживаются JSON и текстовый вывод;

✓ CLI пригоден для автоматизации;

✓ Web и IDE могут использовать CLI как backend.
