# RFC-0010 — Event Bus

**Status:** Draft

**Version:** 0.1

Depends on:

- RFC-0004 Execution Engine
- RFC-0007 Execution Graph
- RFC-0008 Memory
- RFC-0009 Planner

---

# Цель

Определить единственный механизм обмена событиями внутри ICG.

Компоненты системы не должны вызывать друг друга напрямую.

Они должны взаимодействовать через события.

---

# Почему это необходимо

Без Event Bus архитектура быстро превращается в

```
Engine

↓

Memory

↓

Logger

↓

Metrics

↓

Telemetry

↓

UI

↓

Discovery
```

Каждый компонент начинает знать обо всех остальных.

Возникает сильная связанность.

---

# Основной принцип

Компоненты публикуют события.

Компоненты подписываются на события.

Никто не знает,
кто является получателем.

---

# Архитектура

```
Engine

↓

Event Bus

↓

Subscribers
```

---

# Event

Событие —

не команда.

Событие сообщает

что уже произошло.

Например

```
ContractStarted
```

а не

```
StartContract
```

---

# Event Interface

Минимальная структура

```python
class Event:

    id

    type

    timestamp

    payload
```

---

# Event Bus Interface

```python
class EventBus:

    publish(event)

    subscribe(event_type, handler)

    unsubscribe(handler)
```

---

# Публикация

Пример

```
Engine

↓

publish

↓

ContractStarted
```

---

# Подписчики

Например

```
Memory

↓

ContractCompleted
```

```
Metrics

↓

ExecutionFinished
```

```
Logger

↓

ExecutorFailed
```

```
UI

↓

NodeCompleted
```

Все они получают
одно и то же событие.

---

# MVP Events

Минимальный набор

```
ContractCreated

ContractStarted

ContractCompleted

ContractFailed

NodeStarted

NodeCompleted

NodeFailed

ExecutorSelected

ExecutorStarted

ExecutorFinished
```

---

# Payload

Каждое событие содержит

```python
payload

contract_id

node_id

executor

status

duration
```

Payload должен быть сериализуемым.

---

# Event Ordering

Event Bus обязан сохранять порядок событий
в пределах одного Execution.

Например

```
ContractStarted

↓

NodeStarted

↓

ExecutorStarted

↓

ExecutorFinished

↓

NodeCompleted

↓

ContractCompleted
```

---

# Синхронность

Для MVP

Event Bus работает синхронно.

```
publish()

↓

вызвать всех подписчиков

↓

вернуться
```

Позже реализация
может стать асинхронной.

---

# Event Persistence

Event Bus
не обязан хранить события.

За хранение отвечает Memory.

Event Bus —
транспорт.

Memory —
хранилище.

---

# Идемпотентность

Подписчики обязаны
корректно обрабатывать
повторные события.

Например

```
NodeCompleted
```

может быть доставлено повторно.

Обработка должна быть безопасной.

---

# Ошибки

Если один подписчик
завершился с ошибкой,

Event Bus

не должен прекращать
доставку остальным.

Например

```
Logger

↓

Exception
```

не должен останавливать

```
Memory

Metrics

UI
```

---

# Независимость

Event Bus ничего не знает

о

- Engine;

- Planner;

- Graph;

- Executor;

- Memory.

Он знает только события.

---

# Будущее развитие

Позже Event Bus сможет поддерживать

```
Async Dispatch

Priority Events

Distributed Events

Remote Workers

Replay

Persistent Queue

Kafka

NATS

Redis Streams
```

При этом API

```python
publish()

subscribe()
```

не должно измениться.

---

# Пример выполнения

```
User

↓

ContractCreated

↓

PlannerStarted

↓

PlannerCompleted

↓

ContractStarted

↓

NodeStarted

↓

ExecutorSelected

↓

ExecutorStarted

↓

ExecutorFinished

↓

NodeCompleted

↓

ContractCompleted
```

Любой новый компонент
может подключиться
к этой цепочке,
не изменяя существующий код.

---

# Что НЕ входит

Event Bus

не занимается

- маршрутизацией Capability;

- выполнением задач;

- хранением истории;

- выбором Executor.

Он отвечает исключительно
за распространение событий.

---

# Acceptance Criteria

RFC считается реализованным если

✓ существует интерфейс EventBus;

✓ компоненты взаимодействуют через события;

✓ Engine не вызывает Memory напрямую;

✓ Engine не вызывает Logger напрямую;

✓ Event Bus не зависит от конкретных компонентов;

✓ новый подписчик может быть добавлен без изменения Engine;

✓ события сериализуемы;

✓ Event Bus может быть заменен без изменения остальной системы.
