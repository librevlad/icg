# RFC-0012 — Provider SDK

**Status:** Draft

**Version:** 0.1

Depends on:

- RFC-0001 Capability Graph
- RFC-0003 Executor
- RFC-0011 Discovery

---

# Цель

Определить единый SDK для подключения новых Provider.

Добавление нового Provider не должно требовать изменения Engine,
Graph или Policy.

---

# Основная идея

Provider — это плагин.

Любая система,
которая умеет выполнять Capability,
может стать Provider.

---

# Provider Lifecycle

```
Register

↓

Health Check

↓

Benchmark

↓

Execute

↓

Shutdown
```

---

# Интерфейс

```python
class Provider:

    def manifest(self) -> ProviderManifest:
        ...

    def capabilities(self) -> list[Capability]:
        ...

    def healthcheck(self) -> HealthStatus:
        ...

    def benchmark(self) -> BenchmarkResult:
        ...

    def create_executor(
        self,
        capability: Capability
    ) -> Executor:
        ...
```

---

# Manifest

Каждый Provider обязан иметь Manifest.

Минимальная структура

```yaml
id:

name:

version:

author:

homepage:

license:

capabilities:

priority:

cost:

platform:
```

---

# Health Check

Provider обязан уметь сообщить

может ли он работать сейчас.

Например

```
Healthy

Unavailable

Rate Limited

Authentication Failed

Offline
```

---

# Benchmark

Каждый Provider проходит единый Benchmark.

Benchmark используется

для

- Discovery;

- сравнения Provider;

- формирования Capability Profile.

---

# Executor Factory

Provider не выполняет Capability напрямую.

Он создает Executor.

```
Provider

↓

Executor

↓

Execution
```

Это позволяет одному Provider
создавать множество Executor.

---

# Capability Declaration

Provider обязан явно объявить

что он умеет.

Например

```
reasoning

coding

vision

planning
```

Graph не анализирует Provider самостоятельно.

---

# Versioning

Каждый Provider имеет

```
Semantic Version
```

Например

```
1.2.0
```

Discovery отслеживает обновления.

---

# Configuration

Provider получает конфигурацию

через

```yaml
config:
```

Например

```
api_key

binary

timeout

working_directory
```

---

# Secrets

SDK запрещает хранить секреты
в Manifest.

Все секреты

получаются

из Environment
или Secret Store.

---

# Isolation

Provider запрещено

изменять

- Graph;

- Memory;

- Policy;

- Engine.

Он может только создавать Executor.

---

# Packaging

Provider представляет собой обычный пакет.

Например

```
providers/

gemini_cli/

kimi/

groq/

docker/

oracle/
```

или

```
pip install
```

---

# Discovery Integration

Discovery использует SDK
для автоматической регистрации Provider.

Никаких специальных исключений
для отдельных Provider не существует.

---

# Будущее развитие

Позже SDK сможет поддерживать

```
Hot Reload

Remote Providers

WASM Providers

Sandbox

Capability Negotiation

Streaming

Async Execution
```

Без изменения интерфейса Provider.

---

# Acceptance Criteria

RFC считается реализованным если

✓ существует интерфейс Provider;

✓ каждый Provider имеет Manifest;

✓ Provider объявляет Capability;

✓ Provider проходит Health Check;

✓ Provider проходит Benchmark;

✓ Provider создает Executor;

✓ новый Provider подключается без изменения Engine;

✓ Discovery автоматически обнаруживает новый Provider.
