# RFC-0020 — Security Model

**Status:** Draft

**Version:** 0.1

Depends on:

- RFC-0012 Provider SDK
- RFC-0017 Resource Model
- RFC-0018 Distributed Runtime

---

# Цель

Определить модель безопасности ICG.

Security является
отдельным слоем архитектуры.

Никакой компонент
не реализует собственную безопасность.

---

# Главная идея

ICG предполагает,
что Provider,
Worker
и Resource
не являются полностью доверенными.

Все действия
выполняются
по принципу минимально необходимых прав.

---

# Архитектура

```
Policy

↓

Security

↓

Runtime

↓

Worker
```

---

# Trust Levels

Каждый объект
имеет уровень доверия.

```
Trusted

Verified

Unverified

Sandboxed

Blocked
```

---

# Permissions

Capability может требовать

```
filesystem

network

docker

browser

git

shell
```

Security принимает решение

разрешить
или запретить.

---

# Sandboxing

Любой Worker
может быть помещен
в песочницу.

Например

```
Docker

Firecracker

gVisor

VM
```

Архитектура
не зависит
от конкретной реализации.

---

# Secret Management

Ни один Provider

не получает

секреты напрямую.

Все секреты
выдаются Security Layer.

Например

```
API Keys

SSH

Tokens

Passwords
```

---

# Resource Isolation

Worker получает доступ

только

к необходимым Resource.

Например

```
Filesystem

Read Only
```

или

```
Network

Denied
```

---

# Capability Approval

Не каждая Capability
может выполняться автоматически.

Например

```
git push

↓

User Approval
```

или

```
delete files

↓

User Approval
```

---

# Audit Log

Каждое действие

фиксируется.

Например

```
Who

When

Capability

Provider

Worker

Result
```

---

# Policy Integration

Execution Policy
может использовать

Security Layer

при выборе Provider.

Например

```
Untrusted Worker

↓

не использовать
для приватного проекта
```

---

# Remote Workers

Удаленные Worker

получают

минимальный контекст.

Они никогда
не получают
полный проект,
если это не требуется.

---

# Future

Позже Security сможет поддерживать

```
Code Signing

Capability Tokens

Zero Trust

Remote Attestation

Encrypted Artifacts

Trusted Execution Environments
```

---

# Security Principles

ICG придерживается
следующих принципов.

```
Least Privilege

Fail Closed

Zero Trust

Immutable Audit

Explicit Approval
```

---

# Acceptance Criteria

✓ существует Security Layer;

✓ Worker имеет уровень доверия;

✓ Capability требует разрешений;

✓ секреты выдаются централизованно;

✓ существует Audit Log;

✓ удаленный Worker получает только необходимый контекст;

✓ Security отделена от Runtime и Provider.
