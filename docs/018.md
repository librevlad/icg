# RFC-0018 — Distributed Runtime

**Status:** Draft

**Version:** 0.1

Depends on:

- RFC-0007 Execution Graph
- RFC-0015 Scheduler
- RFC-0017 Resource Model

---

# Цель

Определить модель распределенного исполнения ICG.

Execution Graph
не обязан выполняться
на одном компьютере.

---

# Главная идея

ICG рассматривает Интернет
как единый распределенный компьютер.

Execution Graph
может быть разделен
между множеством узлов.

---

# Архитектура

```
Planner

↓

Execution Graph

↓

Scheduler

↓

Runtime

↓

Workers
```

---

# Worker

Worker —

исполнитель.

Он получает
Execution Node
и возвращает результат.

---

# Worker Interface

```python
Worker

execute(node)

heartbeat()

capabilities()

resources()
```

---

# Runtime

Runtime отвечает

за

- доставку задач;

- получение результатов;

- повторные попытки;

- управление Worker.

Runtime не принимает
архитектурных решений.

---

# Worker Registration

Worker обязан зарегистрироваться.

```
Worker

↓

Runtime

↓

Registered
```

После регистрации

Worker становится
доступным Scheduler.

---

# Heartbeat

Каждый Worker
периодически отправляет

```
heartbeat
```

Если Heartbeat отсутствует,

Worker считается Offline.

---

# Task Dispatch

Runtime получает

Execution Node

↓

выбирает Worker

↓

отправляет Node

↓

ожидает результат

---

# Data Locality

Runtime обязан
по возможности

перемещать вычисления
к данным.

Например

```
Repository

↓

Oracle VM

↓

Gemini CLI
```

лучше,

чем

```
Repository

↓

Laptop

↓

Remote API
```

---

# Failure Recovery

Если Worker исчез,

Runtime обязан

- отменить задачу;

или

- переназначить Worker.

Execution Graph
не должен разрушаться.

---

# Stateless Workers

Worker
не обязан хранить состояние.

Все состояние

хранится

в Memory.

---

# Scaling

Добавление нового Worker

не требует

изменения Engine.

Worker автоматически
становится частью Runtime.

---

# Future

Позже Runtime сможет поддерживать

```
P2P Workers

Edge Nodes

Mobile Devices

Serverless

Spot Instances

Volunteer Computing
```

---

# Security

Runtime
не выполняет
авторизацию пользователя.

Он работает
только
с доверенными Worker.

Отдельная RFC
опишет Security Model.

---

# Acceptance Criteria

✓ существует Runtime;

✓ существует Worker Interface;

✓ Worker может зарегистрироваться;

✓ Runtime распределяет Execution Node;

✓ Worker является Stateless;

✓ Runtime поддерживает Heartbeat;

✓ исчезновение Worker не ломает Execution Graph.
