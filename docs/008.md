# RFC-0008 — Memory & Knowledge Graph

**Status:** Draft

**Version:** 0.1

Depends on:

- RFC-0001 Capability Graph
- RFC-0004 Execution Engine
- RFC-0006 Execution Policy
- RFC-0007 Execution Graph

---

# Цель

Определить механизм памяти ICG.

Память не является историей чата.

Память не является векторной базой.

Память представляет собой долговременное знание системы
о выполненных задачах.

---

# Главная идея

ICG должен обучаться
не на датасете,

а на собственном опыте.

Каждый запуск —

новый обучающий пример.

---

# Принцип

Execution

↓

Experience

↓

Memory

↓

Knowledge

↓

Better Decisions

---

# Memory не принимает решений

Memory никогда

не выбирает Executor.

не строит маршрут.

не вызывает LLM.

Она только хранит знания.

---

# Основные сущности

Memory состоит
из трех уровней.

```
Execution Log

↓

Experience

↓

Knowledge
```

---

# Level 1 — Execution Log

Это полный журнал выполнения.

Каждый запуск сохраняет

```
Contract

Execution Graph

Executor

Duration

Status

Artifacts

Errors
```

Журнал никогда
не изменяется.

---

# Level 2 — Experience

Из журнала
формируется опыт.

Например

```
Capability

↓

coding
```

```
Executor

↓

Gemini CLI
```

```
Result

↓

Success
```

```
Duration

↓

12 sec
```

Experience уже
не хранит детали выполнения.

Она хранит
обобщенный факт.

---

# Level 3 — Knowledge

Knowledge —

агрегированное знание.

Например

```
Gemini CLI

coding

↓

92%
```

или

```
Pytest

verification

↓

99%
```

или

```
Gemini

↓

Patch

↓

Pytest

↓

Success

↓

94%
```

Именно этот уровень
используется Policy.

---

# Experience Schema

Минимальная структура

```python
Experience

timestamp

capability

executor

success

duration

workspace

contract_type
```

---

# Knowledge Schema

Минимальная структура

```python
Knowledge

executor

capability

success_rate

average_latency

```

Позже

```
confidence

cost

energy

privacy

token_usage
```

---

# Memory API

Минимальный интерфейс

```python
class Memory:

    append(experience)

    query(...)

    summarize()

    compact()
```

---

# Append Only

Memory является

Append Only.

Удаление истории запрещено.

Изменяются
только агрегированные знания.

---

# Learning

После завершения Execution

Engine вызывает

```
Memory.append()
```

Дальнейшая обработка
происходит отдельно.

Engine не обучает систему.

---

# Query

Policy может запросить

например

```
best executor
for

coding
```

или

```
history

Gemini CLI
```

Memory возвращает
только статистику.

Никаких решений
она не принимает.

---

# Compaction

Со временем

Execution Log

может стать огромным.

Поэтому Memory
должна поддерживать

```
Compaction
```

Старые записи

агрегируются,

но не теряются.

---

# Хранилище

Для MVP достаточно

```
SQLite
```

Таблицы

```
executions

experiences

knowledge
```

Позже могут использоваться

```
DuckDB

PostgreSQL

Neo4j

Parquet

ClickHouse
```

без изменения API.

---

# Knowledge Graph

В будущем

Knowledge
станет графом.

Например

```
Coding

↓

Gemini

↓

Verification

↓

Pytest

↓

94%
```

Таким образом
обучаются уже

не Executor,

а композиции.

Это станет основой
RL-маршрутизации.

---

# Memory ничего не знает

Memory запрещено знать

- Engine

- Planner

- Workspace

- Executor

- Graph

Она хранит
только опыт.

---

# Что НЕ входит

Не описываются

- Vector Search

- Embeddings

- Semantic Memory

- RAG

- LLM Memory

Это будут отдельные RFC.

---

# Будущее развитие

Позже Memory сможет поддерживать

```
Semantic Search

Vector Index

Knowledge Graph

Reinforcement Learning

Capability Embeddings

Failure Prediction

Route Prediction

Experience Replay
```

При этом интерфейс

```python
append()

query()
```

не должен измениться.

---

# Acceptance Criteria

RFC считается реализованным если

✓ существует класс Memory;

✓ Memory является append-only;

✓ после каждого выполнения создается Experience;

✓ Experience агрегируются в Knowledge;

✓ Policy получает статистику только через Memory;

✓ Memory не принимает решений;

✓ смена реализации хранилища не требует изменения Engine.
