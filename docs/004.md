# RFC-0004 — Execution Engine

**Status:** Draft

**Version:** 0.1

Depends on:

- RFC-0001 Capability Graph
- RFC-0002 Contract
- RFC-0003 Executor

---

# Цель

Определить ядро системы ICG.

Execution Engine является единственным компонентом,
который управляет жизненным циклом выполнения Contract.

Engine ничего не знает о конкретных моделях,
CLI, API или способах исполнения.

---

# Ответственность

Engine отвечает исключительно за оркестрацию.

Он обязан

- принять Contract;
- определить необходимые Capability;
- запросить Executor у Graph;
- вызвать Executor;
- собрать результаты;
- вернуть итог выполнения.

Engine не выполняет работу самостоятельно.

---

# Основной цикл

```
Contract

↓

Validate

↓

Resolve Capability

↓

Select Executor

↓

Execute

↓

Collect Result

↓

Next Capability

↓

Complete
```

---

# Единственная точка входа

```python
engine.execute(contract)
```

Все задачи в системе должны проходить через этот метод.

---

# Алгоритм

```
получить Contract

↓

проверить валидность

↓

для каждой Capability

    получить Executor

    выполнить

    сохранить Result

↓

вернуть итог
```

---

# Последовательное выполнение

MVP использует только последовательное выполнение.

Например

```
reasoning

↓

coding

↓

verification
```

Параллельное исполнение запрещено.

---

# Capability Resolution

Engine не знает,

какой Executor использовать.

Он всегда обращается к Graph.

```
Capability

↓

Graph

↓

Executor
```

Никаких

```
if capability == "reasoning":

    GeminiExecutor
```

в Engine существовать не должно.

---

# Выполнение

Engine вызывает

```python
result = executor.run(
    contract,
    workspace
)
```

Никаких других способов исполнения не существует.

---

# Ошибки

Если Executor возвращает

```
success = false
```

Engine прекращает выполнение.

Возвращается итоговый Failure Result.

Повторные попытки (Retry) не входят в MVP.

---

# Результаты

Engine хранит результаты каждого шага.

Например

```
Reasoning

↓

Success

↓

Coding

↓

Success

↓

Verification

↓

Failure
```

Именно эта история затем станет основой обучения.

---

# Engine ничего не знает

Engine запрещено знать

- Gemini

- Claude

- Groq

- Bash

- Docker

- Git

- Pytest

- Playwright

Engine знает только

```
Capability

↓

Executor
```

---

# Workspace

Engine получает Workspace.

Engine передает Workspace Executor.

Engine никогда не работает напрямую
с файловой системой проекта.

Все операции выполняются через Workspace.

---

# Contract State

Engine изменяет только состояние Contract.

Например

```
CREATED

↓

RUNNING

↓

COMPLETED
```

или

```
CREATED

↓

RUNNING

↓

FAILED
```

---

# Execution Context

Во время выполнения Engine формирует Execution Context.

Минимальная структура

```python
ExecutionContext

contract

workspace

results
```

Позже сюда могут добавиться

- metrics;

- memory;

- events;

- telemetry.

---

# Что НЕ делает Engine

Engine запрещено

- строить Prompt;

- запускать subprocess;

- читать Git;

- применять Patch;

- запускать Pytest;

- обращаться к LLM;

- писать в SQLite.

Все это ответственность других компонентов.

---

# Расширяемость

Добавление нового Executor

не должно требовать изменений Engine.

Добавление нового Capability

не должно требовать изменений Engine.

Добавление новой модели

не должно требовать изменений Engine.

---

# MVP

Для MVP достаточно следующего сценария

```
Contract

↓

Reasoning

↓

Coding

↓

Verification

↓

Complete
```

Без

- Retry;

- Fallback;

- Parallel Execution;

- Event Bus;

- RL.

---

# Будущее развитие

В следующих версиях Engine сможет поддерживать

```
Parallel Execution

Retry Policy

Fallback Policy

Capability DAG

Streaming

Cancellation

Timeout

Event Bus
```

Однако публичный API Engine

не должен измениться.

---

# Acceptance Criteria

RFC считается реализованным если

✓ существует класс Engine;

✓ существует метод

```python
engine.execute(contract)
```

✓ Engine не знает конкретных Executor;

✓ Engine получает Executor только через Graph;

✓ Engine не выполняет работу самостоятельно;

✓ Engine не обращается напрямую к файловой системе проекта;

✓ добавление нового Executor не требует изменения Engine;

✓ выполнение Contract полностью управляется Engine.
```
