# RFC-0007 — Execution Graph (DAG)

**Status:** Draft

**Version:** 0.1

Depends on:

- RFC-0001 Capability Graph
- RFC-0002 Contract
- RFC-0004 Execution Engine
- RFC-0006 Execution Policy

---

# Цель

Перейти от линейного списка Capability
к настоящему графу выполнения.

Это RFC является первым фундаментальным
шагом к превращению ICG
из AI-агента
в распределенную операционную систему.

---

# Проблема

В MVP Contract содержит

```yaml
requires:

- reasoning

- coding

- verification
```

Engine выполняет их по порядку.

```
Reasoning

↓

Coding

↓

Verification
```

Такой подход быстро перестанет масштабироваться.

Например

```
Browser

↓

Download

↓

OCR

↓

Reasoning
```

или

```
Planning

↓

├── Coding Backend

├── Coding Frontend

└── Documentation

↓

Verification
```

Невозможно выразить
обычным списком.

---

# Основная идея

Contract описывает

не список Capability,

а граф выполнения.

Execution Engine
выполняет именно граф.

---

# Основные сущности

Появляется новая сущность

```
Execution Node
```

Execution Node —

не Executor.

Execution Node —

это вершина плана выполнения.

---

# Структура

```
Execution Graph

↓

Execution Node

↓

Capability

↓

Executor
```

Capability остается логической.

Executor остается физическим.

Execution Node —
является частью конкретного запуска.

---

# Execution Node

Минимальная структура

```python
ExecutionNode

id

capability

inputs

outputs

dependencies

status
```

---

# Зависимости

Каждая вершина
может зависеть
от других.

Например

```
Planning

↓

Coding

↓

Verification
```

или

```
Planning

↓

├── Backend

├── Frontend

└── Tests

↓

Verification
```

---

# DAG

Execution Graph
обязан быть

Directed Acyclic Graph.

Циклы запрещены.

Например

```
A

↓

B

↓

C
```

допустимо.

```
A

↓

B

↓

A
```

недопустимо.

---

# Валидация

Перед выполнением
Engine обязан проверить

- отсутствие циклов;

- достижимость всех вершин;

- наличие Capability;

- корректность зависимостей.

---

# Выполнение

Engine выполняет
только вершины,
у которых выполнены
все зависимости.

Например

```
Planning

↓

Backend

Frontend

↓

Verification
```

Verification
не может начаться,
пока обе ветви
не завершатся успешно.

---

# MVP

Первая версия Engine
может выполнять DAG

последовательно.

Даже если существует
несколько независимых ветвей.

Например

```
Planning

↓

Backend

↓

Frontend

↓

Verification
```

Позже это станет

```
Planning

↓

Backend   Frontend

↓

Verification
```

без изменения модели данных.

---

# Executor Resolution

Каждый Execution Node

содержит только Capability.

Engine выполняет

```
Capability

↓

Graph

↓

Execution Policy

↓

Executor
```

Execution Node
никогда не хранит Executor.

---

# Status

Каждая вершина
имеет собственное состояние.

Минимально

```
Pending

Running

Completed

Failed
```

Позже

```
Retrying

Cancelled

Skipped

Waiting
```

---

# Артефакты

Execution Node
может создавать

```
Patch

Files

Logs

Reports

Metrics
```

Следующие вершины
получают их как Input.

---

# Ошибка

Если вершина завершилась
с ошибкой

все зависимые вершины

получают статус

```
Skipped
```

Engine не должен
пытаться выполнять их.

---

# Planner

Важно понимать

Execution Graph

не строится Engine.

Он строится Planner.

Engine
только исполняет.

Таким образом

```
Planner

↓

Execution Graph

↓

Engine
```

становятся независимыми.

В будущем Planner
может быть

- Gemini;

- Claude;

- локальная модель;

- человек;

- внешний сервис.

---

# Будущее развитие

Execution Graph
станет основой

для

- Parallel Execution;

- Distributed Execution;

- Remote Workers;

- Cloud Executors;

- Retry;

- Fallback;

- Checkpoint;

- Resume.

Ни один из этих механизмов
не должен менять
структуру DAG.

---

# Что НЕ входит

Execution Graph

ничего не знает

о

- Graph;

- Executor;

- Policy;

- Workspace;

- Memory.

Он является
чистым описанием
процесса выполнения.

---

# Acceptance Criteria

RFC считается реализованным если

✓ существует класс ExecutionGraph;

✓ существует класс ExecutionNode;

✓ ExecutionGraph представляет DAG;

✓ Engine выполняет DAG;

✓ Engine проверяет отсутствие циклов;

✓ ExecutionNode содержит только Capability;

✓ ExecutionNode не знает Executor;

✓ Planner строит граф,
а Engine только исполняет его.
