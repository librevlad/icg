# RFC-0005 — Workspace

**Status:** Draft

**Version:** 0.1

Depends on:

- RFC-0002 Contract
- RFC-0003 Executor
- RFC-0004 Execution Engine

---

# Цель

Определить единственный способ взаимодействия ICG
с проектом пользователя.

Workspace является изолированной рабочей областью.

Никакой компонент системы, кроме Workspace,
не имеет права напрямую работать с файловой системой.

---

# Основная идея

Workspace инкапсулирует

- проект;

- файлы;

- git;

- изменения;

- временные данные.

Engine никогда не вызывает

```
open()

Path()

os.chdir()

subprocess(... cwd=...)
```

напрямую.

Все операции проходят через Workspace.

---

# Ответственность

Workspace отвечает за

- открытие проекта;

- чтение файлов;

- запись файлов;

- создание временных файлов;

- получение списка изменений;

- применение патчей;

- создание снапшотов.

Workspace не принимает архитектурных решений.

---

# Workspace Interface

Минимальный интерфейс

```python
class Workspace:

    def exists(self) -> bool:
        ...

    def read(path: str) -> str:
        ...

    def write(path: str, content: str):
        ...

    def list_files() -> list[str]:
        ...

    def root() -> Path:
        ...
```

---

# Изоляция

Workspace представляет только один проект.

Запрещено

```
../../

/etc

/home

C:\Windows
```

Любые обращения вне Workspace
должны завершаться ошибкой.

---

# Корень Workspace

Каждый Contract выполняется
в пределах одного Workspace.

Например

```
~/projects/point
```

или

```
~/projects/icg
```

Все относительные пути
разрешаются относительно этого каталога.

---

# Работа с файлами

Workspace предоставляет

```python
read()

write()

exists()

delete()
```

Executor никогда
не использует стандартную библиотеку
для работы с файлами напрямую.

---

# Список файлов

Workspace обязан поддерживать

```python
list_files()
```

Возвращается список файлов проекта.

Фильтрация

например

```
.git

venv

node_modules
```

является обязанностью Workspace.

---

# Поиск

Workspace предоставляет

```python
find(pattern)
```

Например

```
*.py

*.md

*.yaml
```

или

```
class User
```

Позже реализация может использовать

- ripgrep

- fd

- sqlite index

без изменения Engine.

---

# Snapshot

Workspace обязан поддерживать создание снимка состояния.

```python
snapshot()
```

MVP может реализовать
его как обычную копию списка файлов.

Позже

Git станет естественной реализацией.

---

# Diff

Workspace предоставляет

```python
diff()
```

Возвращается список изменений.

Engine не вычисляет Diff самостоятельно.

---

# Patch

Workspace предоставляет

```python
apply_patch()
```

Executor может вернуть Patch.

Workspace обязан корректно его применить.

---

# Git

Git не является частью Workspace.

Git представляет отдельный Executor.

Workspace лишь предоставляет доступ
к рабочему каталогу.

Это позволяет в будущем использовать

- Git

- Fossil

- Mercurial

без изменения Workspace.

---

# Временные файлы

Workspace предоставляет

```
tmp/
```

Все промежуточные результаты

должны храниться внутри Workspace.

---

# Безопасность

Workspace запрещает

- абсолютные пути вне проекта;

- символические ссылки наружу;

- запись в системные каталоги.

Это защищает Executor
от случайного повреждения системы.

---

# Будущее развитие

Позже Workspace сможет поддерживать

```
Multiple Workspace

Remote Workspace

Docker Workspace

SSH Workspace

Oracle Workspace

GitHub Workspace

Memory Workspace
```

При этом публичный API
не должен измениться.

---

# Что НЕ входит

Workspace ничего не знает

о

- Graph;

- Capability;

- Engine;

- Memory;

- Event Bus;

- Statistics.

Он занимается исключительно
рабочей директорией.

---

# Acceptance Criteria

RFC считается реализованным если

✓ существует класс Workspace;

✓ Engine не работает напрямую с файловой системой;

✓ Executor получает только Workspace;

✓ чтение и запись файлов происходят исключительно через Workspace;

✓ Workspace способен создать Snapshot;

✓ Workspace способен вернуть Diff;

✓ Workspace способен безопасно применять Patch;

✓ смена реализации Workspace не требует изменения Engine или Executor.
