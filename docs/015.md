# RFC-0015 — Scheduler

**Status:** Draft

**Version:** 0.1

Depends on:

- RFC-0007 Execution Graph
- RFC-0009 Planner
- RFC-0010 Event Bus

---

# Цель

Отделить исполнение DAG
от принятия решения
о порядке исполнения.

Execution Engine отвечает
за выполнение.

Scheduler отвечает
за порядок выполнения.

---

# Главная идея

Engine должен стать максимально простым.

Он не решает

- что запускать;
- когда запускать;
- параллельно или нет;
- что можно отложить.

Все эти решения принимает Scheduler.

---

# Архитектура

```
Execution Graph

↓

Scheduler

↓

Ready Queue

↓

Engine

↓

Executor
```

---

# Ответственность

Scheduler обязан

- анализировать DAG;
- находить готовые вершины;
- определять порядок исполнения;
- управлять очередями;
- соблюдать ограничения.

Scheduler запрещено

- выполнять Executor;
- обращаться к Provider;
- выбирать Capability.

---

# Интерфейс

```python
class Scheduler:

    def next(
        graph: ExecutionGraph
    ) -> list[ExecutionNode]:
        ...
```

---

# MVP

Scheduler работает
по принципу Topological Order.

Алгоритм

```
найти все вершины,
у которых зависимости выполнены

↓

вернуть их
```

---

# Ready Queue

Scheduler формирует очередь

```
Pending

↓

Ready

↓

Running

↓

Completed
```

---

# Constraints

Scheduler обязан учитывать

```
max_parallelism

priority

dependencies

timeout
```

Даже если
они пока не используются.

---

# Retry

Scheduler не выполняет Retry.

Он лишь принимает решение

можно ли повторить вершину.

---

# Cancellation

Scheduler обязан поддерживать

```
Cancelled

Skipped
```

Это потребуется
для будущего распределенного исполнения.

---

# Future

Позже Scheduler сможет учитывать

```
CPU

GPU

Network

Provider Load

Cost

Energy

User Priority
```

Без изменения API.

---

# Acceptance Criteria

✓ существует Scheduler;

✓ Scheduler работает только с DAG;

✓ Engine не определяет порядок выполнения;

✓ Scheduler можно заменить без изменения Engine.
