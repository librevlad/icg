# RFC-0001 — Capability Graph

**Status:** Draft

**Version:** 0.1

---

# Цель

Определить фундаментальную модель Internet Capability Graph.

ICG не маршрутизирует запросы к LLM.

ICG маршрутизирует способности (Capabilities).

Все остальные компоненты системы строятся вокруг этой идеи.

---

# Проблема

Большинство современных AI-агентов принимают решение так:

```
Task

↓

Model

↓

Result
```

или

```
Task

↓

Planner

↓

Router

↓

LLM
```

Это делает систему зависимой от конкретных моделей.

При появлении новой модели необходимо менять код маршрутизации.

ICG должен быть полностью независим от конкретных моделей.

---

# Основной принцип

ICG знает только способности.

Например

```
Reasoning

Coding

Planning

Execution

Verification

Browser

Vision

Memory

Git

Compilation

Testing
```

ICG никогда не принимает решения вида

```
использовать Gemini
```

Он принимает решение

```
нужна способность Reasoning
```

Далее Graph определяет, какой исполнитель способен предоставить эту способность.

---

# Основные сущности

## Capability

Capability представляет собой абстрактную возможность выполнить некоторый тип работы.

Capability является логической сущностью.

Она ничего не знает о конкретных моделях.

Примеры:

```
reasoning

planning

coding

verification

execution

browser

vision

git

memory
```

---

## Executor

Executor представляет конкретный инструмент.

Например

```
Gemini CLI

Claude Code

Bash

Pytest

Git

Playwright
```

Executor может реализовывать несколько Capability.

Например

```
Gemini CLI

↓

reasoning

planning

coding
```

---

## Graph

Graph связывает Capability и Executor.

Например

```
reasoning

↓

Gemini CLI

↓

Claude Code
```

или

```
verification

↓

Pytest
```

---

# Первичная архитектура

```
Task

↓

Contract

↓

Capability Graph

↓

Executor

↓

Result
```

Engine никогда не обращается к Executor напрямую.

Engine всегда работает через Graph.

---

# Capability Resolution

Запрос выполняется следующим образом.

```
Need:

reasoning
```

Graph возвращает

```
Gemini CLI
```

или

```
Claude Code
```

или любой другой Executor.

Engine не знает, почему был выбран именно этот Executor.

---

# Первое ограничение MVP

Graph может использовать самое простое правило выбора.

Например

```
выбрать первый доступный Executor
```

или

```
выбрать Executor с максимальным приоритетом
```

Без обучения.

Без статистики.

Без RL.

---

# Будущее развитие

Graph должен постепенно перейти к использованию весов.

Например

```
Capability

↓

Edge

↓

Executor
```

где ребро хранит

```
success_rate

latency

cost

availability

last_used
```

Позже выбор будет выполняться на основании этих характеристик.

---

# Что НЕ входит в RFC

Не описываются

- Contract

- Workspace

- Engine

- Memory

- Event Bus

- Learning

Эти компоненты определяются отдельными RFC.

---

# Acceptance Criteria

ICG считается реализованным согласно RFC, если

- существует объект Graph;

- существует объект Capability;

- существует объект Executor;

- Engine получает Executor только через Graph;

- Engine не содержит упоминаний Gemini, Claude, Groq или любых других конкретных инструментов.

```
Engine

↓

Graph

↓

Executor
```

является единственным допустимым способом исполнения Capability.
