# RFC-0021 — Benchmark Suite

**Status:** Draft

**Version:** 0.1

Depends on:

- RFC-0011 Discovery
- RFC-0012 Provider SDK
- RFC-0013 Capability Schema
- RFC-0016 Route Learning

---

# Цель

Определить единый стандарт оценки Provider, Capability и Route.

Без Benchmark
Graph не способен
принимать объективные решения.

---

# Главная идея

ICG не доверяет заявлениям Provider.

Любая Capability
должна подтверждаться
реальным выполнением задач.

---

# Архитектура

```
Provider

↓

Benchmark Suite

↓

Benchmark Result

↓

Memory

↓

Capability Graph
```

---

# Benchmark

Benchmark —

детерминированный набор задач,
имеющий известный ожидаемый результат.

---

# Benchmark Model

Минимальная структура

```python
Benchmark

id

name

capability

input

expected_output

constraints

score
```

---

# Benchmark Categories

MVP

```
Reasoning

Coding

Refactoring

JSON

Patch Editing

Testing

Documentation
```

---

# Scoring

Каждый Benchmark
возвращает

```
Success

Latency

Cost

Artifacts

Logs
```

На их основе
формируется итоговый Score.

---

# Capability Score

Capability получает
независимую оценку.

Например

```yaml
coding

accuracy:

0.94

latency:

3.1

cost:

free
```

---

# Route Benchmark

Benchmark может проверять

не только Provider,

но и целые маршруты.

Например

```
Planning

↓

Gemini

↓

Coding

↓

Kimi

↓

Verification

↓

Pytest
```

Именно это используется
Route Learning.

---

# Continuous Benchmarking

Discovery может
повторно запускать
Benchmark.

Это позволяет замечать

- деградацию;
- улучшение;
- изменение поведения Provider.

---

# Reproducibility

Все Benchmark

должны быть

детерминированными.

Одинаковый вход

↓

одинаковый ожидаемый результат.

---

# Benchmark Registry

Benchmark
хранятся отдельно.

```
benchmarks/

coding/

reasoning/

verification/
```

Любой Provider
проходит одинаковый набор тестов.

---

# Community Extensions

Новые Benchmark
могут добавляться
без изменения ядра.

Discovery автоматически
обнаруживает их.

---

# Anti-Overfitting

Benchmark Suite

не должен состоять
из одного теста.

Каждая Capability
оценивается
множеством независимых сценариев.

---

# Acceptance Criteria

✓ существует Benchmark Model;

✓ Benchmark имеет ожидаемый результат;

✓ Provider проходит Benchmark;

✓ Capability получает Score;

✓ Route может оцениваться;

✓ Benchmark Registry расширяем.
