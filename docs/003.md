# RFC-0003 — Executor

**Status:** Draft

**Version:** 0.1

Depends on:

- RFC-0001 Capability Graph
- RFC-0002 Contract

---

# Цель

Определить единый интерфейс исполнения задач.

Executor является единственным компонентом системы, который знает,
как использовать внешний инструмент.

Engine никогда не работает напрямую с

- Gemini
- Claude
- Bash
- Pytest
- Docker
- Git

Он работает исключительно через Executor.

---

# Основная идея

Executor представляет адаптер между внутренним миром ICG
и внешним инструментом.

Например

```
Gemini CLI

↓

GeminiCLIExecutor
```

или

```
Git

↓

GitExecutor
```

или

```
Pytest

↓

PytestExecutor
```

---

# Ответственность

Executor обязан

- получить Contract;

- получить Workspace;

- выполнить работу;

- вернуть Result.

Executor никогда не принимает решений.

Он только исполняет.

---

# Executor Interface

Минимальный интерфейс

```python
class Executor:

    def capabilities(self) -> list[Capability]:
        ...

    def run(
        self,
        contract: Contract,
        workspace: Workspace,
    ) -> ExecutionResult:
        ...
```

---

# Capability Declaration

Каждый Executor обязан явно объявить,
какие Capability он реализует.

Например

```python
GeminiCLIExecutor

↓

reasoning

planning

coding
```

или

```python
PytestExecutor

↓

verification
```

Graph использует именно этот список.

---

# ExecutionResult

Каждый Executor обязан возвращать объект.

Минимальная структура

```python
ExecutionResult

success

stdout

stderr

artifacts

duration
```

---

# Artifacts

Executor может создавать артефакты.

Например

```
patch.diff

report.json

coverage.xml

test.log
```

Engine не анализирует stdout.

Он работает только с объектом Result.

---

# Ошибки

Executor никогда не выбрасывает необработанные исключения.

Все ошибки превращаются в ExecutionResult.

Например

```
success = false

stderr = ...

error_code = ...
```

Engine должен получать одинаковый интерфейс
независимо от причины ошибки.

---

# Executor не знает Graph

Executor запрещено обращаться к

- Graph;

- Memory;

- другим Executor.

Executor является полностью изолированным.

---

# Executor не знает Planner

Executor не должен анализировать задачу.

Он получает уже готовый Contract.

Никаких решений внутри Executor не принимается.

---

# Один Executor — много Capability

Допускается

```
GeminiCLIExecutor

↓

reasoning

planning

coding

review
```

Это считается одним Executor.

---

# Capability не равна команде

Например

```
Capability

↓

coding
```

может внутри Executor вызвать

```
gemini \
  --mode edit
```

или

```
gemini \
  --mode generate
```

Это внутренняя логика Executor.

Graph этого не знает.

---

# Workspace

Executor имеет доступ только к Workspace,
переданному Engine.

Запрещено

- менять текущий Workspace;

- обращаться к произвольным каталогам;

- изменять другие проекты.

---

# Логирование

Executor не пишет в базу данных.

Не отправляет события.

Не изменяет Graph.

Он возвращает только Result.

---

# MVP Executors

Для первой версии системы достаточно реализовать

```
GeminiCLIExecutor

BashExecutor

PytestExecutor
```

Этого достаточно,
чтобы доказать работоспособность архитектуры.

---

# Будущее расширение

Позже могут появиться

```
ClaudeCodeExecutor

GroqExecutor

DockerExecutor

PlaywrightExecutor

GitExecutor

BrowserExecutor

OracleExecutor

KimiExecutor

OpenAIExecutor
```

Engine не должен измениться
после добавления любого нового Executor.

---

# Acceptance Criteria

RFC считается реализованным если

✓ существует базовый класс Executor;

✓ каждый Executor явно объявляет свои Capability;

✓ Engine работает только через Executor;

✓ Executor возвращает ExecutionResult;

✓ Executor не знает Graph;

✓ Executor не знает Memory;

✓ Executor не принимает архитектурных решений;

✓ новый Executor можно добавить без изменения Engine.
```
