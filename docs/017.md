# RFC-0017 — Resource Model

**Status:** Draft

**Version:** 0.1

Depends on:

- RFC-0001 Capability Graph
- RFC-0012 Provider SDK
- RFC-0013 Capability Schema

---

# Цель

Определить универсальную модель ресурсов.

Provider —
это источник Capability.

Resource —
это то,
что Provider использует
для выполнения Capability.

---

# Главная идея

Сегодня большинство систем
путают Provider и Resource.

Например

```
Oracle VM
```

это не Provider.

Это набор ресурсов.

```
CPU

RAM

Filesystem

Network

Docker
```

---

# Архитектура

```
Capability

↓

Provider

↓

Resource
```

Provider использует Resource.

Capability требует Resource.

---

# Resource

Минимальная структура

```python
Resource

id

type

state

capacity

availability

metadata
```

---

# Типы ресурсов

MVP определяет

```
CPU

GPU

RAM

Filesystem

Network

Process

Docker

Browser

LLM

Storage
```

Позже список расширяется.

---

# Capacity

Каждый ресурс имеет емкость.

Например

```
CPU

4 cores
```

или

```
RAM

24 GB
```

или

```
LLM

1M context
```

---

# Availability

Каждый ресурс имеет состояние.

```
Available

Busy

Offline

Limited

Unknown
```

---

# Resource Graph

Ресурсы
образуют отдельный граф.

```
Oracle VM

↓

CPU

↓

Docker

↓

Filesystem

↓

Network
```

Execution Policy
может учитывать
этот граф.

---

# Resource Constraints

Capability может требовать

```
GPU

или

Filesystem

или

Network
```

Policy обязана
проверять совместимость.

---

# Dynamic Resources

Некоторые ресурсы
меняются во времени.

Например

```
Free RAM

CPU Load

Network

Rate Limit
```

Graph должен поддерживать
обновление этих значений.

---

# Composite Resources

Resource может состоять
из других ресурсов.

Например

```
Oracle VM

↓

CPU

RAM

Filesystem

Docker
```

---

# Remote Resources

Resource может находиться

```
локально

или

удаленно
```

Архитектура
не делает различий.

---

# Discovery

Discovery
может обнаруживать

новые ресурсы

независимо
от Provider.

---

# Resource Identity

Каждый Resource
имеет постоянный ID.

Например

```
oracle-arm-01

↓

cpu

↓

cpu0
```

---

# Future

Позже Resource сможет содержать

```
Power Usage

Carbon Cost

Reliability

Geography

Bandwidth

Security Level
```

---

# Acceptance Criteria

✓ существует модель Resource;

✓ Provider использует Resource;

✓ Resource имеет состояние;

✓ Resource имеет Capacity;

✓ Resource Graph независим от Capability Graph;

✓ Policy может учитывать Resource.
