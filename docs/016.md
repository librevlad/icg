# RFC-0016 — Route Learning

**Status:** Draft

**Version:** 0.1

Depends on:

- RFC-0008 Memory
- RFC-0011 Discovery
- RFC-0015 Scheduler

---

# Цель

Определить механизм,
позволяющий ICG обучаться
не отдельным Provider,
а маршрутам выполнения.

Это основной механизм
самооптимизации системы.

---

# Главная идея

Современные роутеры
оценивают модели.

ICG оценивает маршруты.

Например

```
Gemini

↓

Pytest
```

может работать лучше

чем

```
Claude

↓

Pytest
```

Хотя отдельно
Claude сильнее.

---

# Route

Route —

последовательность

```
Capability

↓

Provider

↓

Capability

↓

Provider
```

которая привела
к успешному результату.

---

# Route Identity

Каждый маршрут
имеет собственный идентификатор.

Например

```
Planning

↓

Gemini

↓

Coding

↓

Kimi

↓

Verification

↓

Pytest
```

---

# Experience

После каждого выполнения
создается Experience.

Из него извлекается Route.

Например

```yaml
route:

planning:

gemini

coding:

kimi

verification:

pytest

success:

true

duration:

34
```

---

# Route Profile

Для каждого маршрута
накапливается статистика.

```yaml
success_rate:

0.94

average_duration:

28

executions:

164
```

---

# Learning

Каждое успешное выполнение

усиливает

Route Score.

Каждая ошибка

уменьшает его.

---

# Route Score

Минимальная модель

```
Score

=

Success Rate

×

Confidence

×

Freshness
```

Позже могут добавиться

- Cost;

- Latency;

- Energy;

- Privacy.

---

# Exploration

ICG обязан
периодически исследовать
новые маршруты.

Например

```
90%

лучший Route

10%

новый Route
```

Без Exploration

обучение прекращается.

---

# Exploitation

Основной режим работы

использует

лучшие известные маршруты.

---

# Route Aging

Если маршрут
не использовался долго,

его Confidence
уменьшается.

Это позволяет системе
адаптироваться
к изменениям Интернета.

---

# Route Composition

Route может состоять
из нескольких ветвей DAG.

Позже

ICG сможет обучать

не только линейные маршруты,

но и целые подграфы.

---

# Memory Integration

Route Learning
не хранит данные самостоятельно.

Все данные
берутся из Memory.

---

# Policy Integration

Execution Policy
может запросить

```
Best Route

for

Task Type
```

Memory возвращает
статистику.

Policy принимает решение.

---

# Future

Позже Route Learning
сможет использовать

```
Contextual Bandits

Bayesian Optimization

Monte Carlo Tree Search

Reinforcement Learning

Graph Neural Networks
```

Без изменения модели Route.

---

# Scientific Contribution

Главная гипотеза ICG

заключается в том,

что

оптимальным объектом обучения

является

не модель,

не Provider,

а композиция маршрута.

Именно Route становится
единицей знания системы.

---

# Acceptance Criteria

✓ существует сущность Route;

✓ Route строится автоматически после выполнения;

✓ для Route накапливается статистика;

✓ Route имеет Score;

✓ Policy может использовать Route Score;

✓ система обучается маршрутам, а не отдельным Provider.
